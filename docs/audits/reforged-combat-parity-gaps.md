# Computational combat parity: findings and implementation order

This is the initial discrepancy snapshot, before the runtime changes in
`e603d81` and `3b83279`. The matrix, weapon delivery, acquisition, training
times and transport capacity have since been corrected in the represented
runtime roster. See [the implemented changes and remaining limits](../VALIDATION-v0.22-WATER-COMBAT.md).
The complete catalog and dynamic modes remain separate outstanding work.

Source: `Risk_Reforged_v3.0_by_Saran_OPEN_SOURCE.w3x`, extracted W3U/W3A/W3Q/JASS, and local owned-disc RoC and TFT text tables. The canonical metadata-based result is `data/derived/reforged-source-combat.json`, generated by `python scripts/resolve_source_combat.py`; it covers all 69 W3U records, both weapons, profiles, relevant abilities, upgrades and mode-specific rosters. The older companion table remains the first-pass RoC-only audit.

## Evidence limits

The files named `TFT121b-Resolved-Unit*.slk` are binary patch deltas, not text SLK. The resolver instead reads complete text SLKs and profiles extracted from the owned TFT installer payload and maps real W3U field IDs through `UnitMetaData.slk`. Those values remain historical candidates: W3I declares Reforged `2.0.2.22796`, and `game_data_set=0` means default data rather than selecting a RoC/TFT balance set. Fields where RoC and TFT differ are marked `classic_conflict_do_not_replace_runtime`; missing values remain unresolved.

## Dynamic rules that prevent a static-table parity claim

JASS researches `Rhri` at lines4740,4800,7970,7981,8525,8530 and removes it at5244; the surrounding mode/turn conditions matter. `R000` and `R001` are also researched/removed. The full W3Q (1026 bytes) is now parsed into the JSON: Rhri explicitly replaces effect1 with `renw` (WTS TRIGSTR_3941), base1=1.0, so it must NOT be treated as the stock Long Rifles range bonus. Resolve upgrade effect metadata before implementing it. R000 inherits Rhme unchanged, R001 inherits Rhar unchanged. R002 uses rats/.06 plus ratt; R003 uses rhpo/.06 plus rarm; R004 uses rmov/.10 plus rarm. These custom effects and unit uupg lists need application, not a guessed +200 range. JASS at7813–7815 and7955–7957 changes **weapon index1** base/dice/sides, not weapon0. HP is dynamically changed at19715 and regeneration at19718. The generated JSON records technology/damage/HP mutation lines for follow-up.

## Proposed implementation sequence

1. Obtain matching Reforged 2.0.2.22796 game data or original-engine observations for fields marked conflict/TFT-only/unresolved. The metadata-based resolver and JASS roster graph are now present.
2. Introduce all source attack/armor categories and matrix. Preserve original rawcode/type strings in data. Keep capture behavior distinct from destructible building combat.
3. Introduce weapon profiles independent of damage type: instant/melee/missile/artillery, target flags, minimum/maximum/acquisition range, damage point, cooldown, missile speed, splash bands/factors, upgrade effects. Replace hardcoded projectile/splash/range adapters only where source evidence is resolved.
4. Verify deterministic damage distributions, damage matrix, instant versus delayed hits, range boundaries, dynamic Rhri transitions, and every exposed rawcode. Do not use tests that merely restate copied constants as proof of engine parity. Validate selected cases against original engine observations when available.

No runtime files were changed by this audit, and no Unity session was launched.
